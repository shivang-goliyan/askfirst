The problem is not that it was wrong. It is that it was certain and wrong, and nothing in the output separated that case from a correct one.

Our own run, logged, checksums kept. Published corroboration: MeasureBench (arXiv 2510.26865) — a frontier model at 19.8% on measurement reading, 2.0% on composite gauges.
What it is

Not a diagnosis tool. A gate in front of the model that decides.

It answers a narrower and far more answerable question: is there enough here?

  1. Record split into atomic fields.
  2. Open model scores it — the full distribution is kept, not a sampled answer.
  3. Each present field removed in turn → what the answer rests on.
  4. Each absent field ranked by expected information gain, then by cost and minutes.
  5. Unstable under ablation → refuse, return the ranked gaps, hand over.

Why this needs an open model, on AMD

The product is built on the distribution. A closed API returns text.

Entropy, information gain and a calibrated threshold are all functions of the full posterior. There is no version of this that works behind an API that hands back a sentence.

POST /v1/completions   { "echo": true, "max_tokens": 0, "logprobs": 1 }
→ token_logprobs + text_offset over the prompt
   one round trip per label set · vLLM on MI300X, 192 GB HBM3
A better model does not make the answers cheaper. It makes more of them answerable.

The CPU baseline bottoms out at 5% coverage because a naive Bayes is 21% accurate overall. A stronger scorer moves that optimum to higher coverage at the same cost — a strictly better product, measured against a baseline that already exists.

What we got wrong, with dates on it

Four dead ends are in the repo. One of them is ours.

  • Our first ranking objective made things worse than guessing. Following its advice scored 18.8% against 26.0% for asking at random and 28.0% for asking nothing. Flip probability selects for volatility, not information. Replaced with expected information gain → 28.4%, harm gone.
  • A d-dimer shows why: 0.264 bits of information at a flip probability of 0.00. It settles the question without changing the leading answer, and the old objective could not see it.
  • Cheap-proposes-then-model-ablates caps the system near 32% — shortlist recall at k=20 is 31.8% and stage two can only re-rank what stage one passes. Inverted.
  • The advice half is neutral, not useful: 28.4% against 26.0%, intervals overlapping. It ships as a visible aid, not as a claim.
Every failure is dated and committed in docs/results/ — in the order it happened

Prior work — said by us, before it is said to us

MediQ posed the interactive version of this first. We are not claiming the idea.

  • MediQ, NeurIPS 2024, arXiv 2406.00922 — naive prompting to ask questions lowered accuracy by 11.3%. Their self-consistency fix gave +22.3%, leaving a 10.3% gap against full information. That is the number to beat, and it is a real target rather than a vague one.
  • Q4Dx, Nature Scientific Reports 2026 — an evaluation built by systematically removing information from cases. That is our evaluation design, already published.
  • ALFA (arXiv 2502.14860), BALAR / MedClarify — expected information gain over a fixed question set.

What we have not found occupied: ranking the absent fields by counterfactual influence over an open model's own logprobs. Absence of search evidence is not proof, and we say so rather than claiming a gap.

The same engine, a second domain

Variant interpretation, where the evidence contradicts itself.

CIViC — public, CC0, 4,940 evidence rows. Grouped by variant and outcome: 585 groups where removing one line of evidence can change the call, of which 182 are contested — the same knowledge base both supports and does not support the conclusion.

Demo case: DNMT3A R882 in AML. Level-B evidence on both sides, at ratings 3 and 4. Most tools average that. This one reports that the case is unresolved and names the evidence doing the damage.

The limit, in the same breath: 182 groups is a demonstration, not a headline. Module A carries the measurement. Computational evidence stays capped at "supporting" strength, which is what ACMG/AMP actually allows.

Who pays, and what it costs to run

The buyer is anyone already carrying the cost of a model's confident mistakes.

  • Triage and teleconsult services deciding what to do with an incomplete intake.
  • Decision-support vendors who need a safety layer they can show a regulator.
  • Lab networks choosing which test to run next, where the ranking is the product.

One assessment is one generation plus a sweep the CPU does for free. The expensive design was the obvious one: an exhaustive 223-field sweep with a language model costs about 22 seconds of GPU per case — a latency wall that does not move with more credits. So the model proposes roughly ten fields in a single pass and the cheap scorer ablates exhaustively at no cost.

It knows when it doesn't know. That's the product.
